# プロダクト要件定義書（PRD）：オーディション採点アプリ

## 1. プロダクト概要（Overview & Context）

### 1.1. 背景と手動運用の課題
- 従来、部内オーディションにおいてGoogleフォーム、スプレッドシート、Excelを組み合わせた手動運用を行っていた。
- 所属部員約100名、エントリー最大32バンド規模のイベントにおいて、データ転記や関数操作に伴うヒューマンエラー（集計ミス）のリスクが高頻度で発生しており、集計・転記プロセス自体の完全自動化が求められていた。
- 自バンド（自身が出演・所属するバンド）に対する採点の混入防止チェックが手動であり、不正や計算・除外漏れが生じやすかった。

### 1.2. 目的・ビジョン
- 採点入力からペナルティ減点・自バンド自動除外・リアルタイム自動集計までをWebアプリ上で一元化し、集計ミスゼロおよび運用工数の大幅削減を実現する。
- 透明性・信頼性の高い集計アルゴリズムとExcel/CSV形式でのデータ出力機能を提供し、公平な評価環境を提供する。

---

## 2. プロジェクトの境界線（Goals, Non-Goals, Future Scope）

### 2.1. Goals（達成要件・実装済み範囲）
- **大規模同時入力と永続化**：最大32バンド・100人規模の同時採点に対応するWebフォームおよびデータ永続化。オフライン時の端末ローカル下書き保存（`localStorage`）と自動同期。
- **プライバシーに配慮した認証と部員マスタ管理**：学内Google OAuth認証、学籍番号のHMAC-SHA256不可逆ハッシュ照合（DBに生の学籍番号・メールアドレスを保存しない設計）、大学提出用部員名簿Excel/CSV/TSVからの一括取り込み、初回ログイン時の氏名・回生確認モーダル。
- **自バンド自動除外（複数掛け持ち対応）**：自分が所属するすべてのバンドを採点画面で自動非表示・ロックし、APIおよび集計エンジンでも確実に除外。
- **リアルタイム採点・誤操作防止・全体講評**：魅力点・技術点（各0〜50）と合計点のリアルタイム表示、コメントおよび全体講評の必須バリデーション、保存時のカード自動折りたたみによるスマホ誤操作防止ロック、提出前の「マイ順位確認」プレビュー。
- **出演バンド登録・共同編集・出演順管理**：バンド募集中（`DRAFT`）の全部員によるバンド登録・メンバー選択（現役1〜3回生から検索選択）、募集締切日時（`entry_deadline`）またはステータス変更による自動ロック、管理者による出演順プルダウン設定（自動入れ替え対応）および一括登録。
- **提出ステータス管理・未公開制御**：提出状況モニタリング（未提出者フィルタ・LINE貼付用リストコピー）、採点必須者全員が提出完了するまでの結果非表示ガード（管理者プレビュー対応）。
- **非破壊正規化集計・ペナルティ管理**：Min-Max正規化（既定定数100・1〜100で変更可）／Zスコア正規化／単純平均方式のワンクリック切替・3方式比較列・アルゴリズム解説モーダル、オーディション単位のペナルティ有効化トグルとバンド単位の非破壊減点。
- **2ファイル構成のExcel/CSVエクスポート**：集計結果＆全採点データ＆全体講評（3シート構成）およびバンド別講評シート（各バンド1シート＋全体講評シート）のExcel/CSV出力。

### 2.2. Non-Goals（非対応・スコープ外）
- **メディア配信**：オーディション当日の動画・音源ストリーミング配信機能。
- **外部システム連携**：部費決済・外部会計システムとの連動機能。
- **高度なグラフ描画**：アプリ内での動的な複雑なグラフ描画（集計テーブルとExcel/CSV出力で代替）。
- **手動スコアオーバーライド**：管理者による最終スコア・順位の直接手動オーバーライド機能。

### 2.3. 将来的な拡張案（Future Scope）
- **自動リマインド通知機能**：Cloudflare Workers の Cron Triggers 等を活用した、締切前の未提出者への自動リマインド通知。

---

## 3. 対象ユーザーと利用シーン（Target Users & User Stories）

### 3.1. ターゲットユーザー区分
- **一般部員（`VOTER`）**：オーディション参加・鑑賞中、または録画視聴中にスマホ・PCから採点・コメント・全体講評を入力し、結果公開後にランキングや講評を閲覧する約100名の部員。
- **渉外・運営委員（`ADMIN`）**：部員名簿の登録、イベント作成、バンド募集・出演順・採点義務の設定、進行ステータス管理、提出状況監視、ペナルティ入力、集計・Excel出力を行う管理ユーザー。

### 3.2. ユーザーストーリー
- 採点者として、自分が所属するバンドは自動で採点対象外になり、技術点・魅力点の合計計算や入力途中の下書き保存をシステムに任せたい。
- 運営者として、100名の採点データやペナルティ減点が即座に自動反映された正確なランキングを確認し、未提出者をすぐに把握してリマインドしたい。

## 4. 機能要件（Functional Requirements）

### 4.1. 認証・部員マスタ・権限管理
- **学内Google OAuth認証**：`@hono/oauth-providers/google` を用いた学内ドメイン限定（`ALLOWED_GOOGLE_DOMAIN`）ログインと、HMAC-SHA256署名済み `HttpOnly` Cookie セッション（有効期限7日間）。
- **学籍番号ハッシュによるプライバシー保護**：メールアドレスの `@` より前（学籍番号）を正規化し、`STUDENT_ID_HASH_SECRET` で HMAC-SHA256 ハッシュ化した値（`student_id_hash`）および Google ユーザーID（`google_sub`）のみをDBへ保存し、生の学籍番号・メールアドレスは保持しない。
- **スーパーユーザー自動設定**：環境変数 `INITIAL_ADMIN_EMAILS` に一致するアカウントは初回ログイン時に自動で `ADMIN` ロールを付与。
- **初回ログイン時の氏名・回生確認**：一括登録で入部年度が推定値の場合や初回自動作成アカウントの場合、ログイン直後にモーダルを表示し、氏名（「苗字 名前」形式）と現在の回生（入部年度）を本人に確定させる。
- **部員名簿の一括取り込み**：
  - 大学提出用部員名簿Excel（`.xlsx` / `.xls`）および `.csv` をブラウザ上で解析し、「学籍番号」「氏名」列のみを抽出して登録（タイトル行・顧問教員・空行・記入例を自動除外、不要な個人情報はサーバー非送信）。
  - Excelからのコピー＆ペースト（TSV）およびCSV入力にも対応（列順の自動スワップ、重複学籍番号のスキップ）。
- **部員権限管理・削除**：管理画面から `ADMIN` / `VOTER` の即時切替（最後の1人の `ADMIN` 降格を防止）および部員削除（自分自身および最後の `ADMIN` 削除を防止）。
- **入部年度からの動的回生算出**：4月1日（JST）基準で回生を自動計算し、現役部員（1〜3回生）をバンドメンバー候補・採点義務設定の対象として自動フィルタリング。
- **ローカル開発用ダミーログイン**：`ENABLE_DEV_LOGIN` 有効時のみ、ワンクリックで権限別テストアカウントへ切り替え可能。

### 4.2. 採点フォーム・入力機能
- **点数・コメント・全体講評の入力**：
  - 魅力点（0〜50）・技術点（0〜50）を数値入力またはスライダーで入力し、合計点（100点満点）をリアルタイム表示。
  - 参加権限（`audition_voters`）に応じた動的バリデーション：
    - **採点＋コメント（`SCORE_AND_COMMENT`）**：魅力点・技術点・各バンドコメント・全体講評のすべてを必須とする。
    - **コメントのみ（`COMMENT_ONLY`）**：点数入力欄を非表示にし、サーバー側でも `tech_score = null` / `charm_score = null` を強制。各バンドコメント・全体講評を必須とする。
    - **未登録（不参加）**：専用案内画面を表示し、採点・提出を拒否。
- **自バンド自動除外**：ログインユーザーが `band_members` に登録されているすべてのバンドを採点対象外としてグレーアウト表示し、API・集計からも除外。
- **スマホ誤操作防止（保存時自動折りたたみ）**：各バンドの「採点を保存」を押すとカードがコンパクトなロック表示へ折りたたまれ、スクロール時のスライダー誤操作を防止。「編集」ボタンで再編集可能。
- **採点締切（`scoring_deadline`）制御**：締切超過後は提出済みユーザーの修正を完全ロック。未提出ユーザーは保存済み項目の変更不可とし、未入力のバンド・全体講評のみ入力および初回最終提出を許可。
- **マイ順位確認＆オフライン対応**：提出前に自分が付けた点数・順位・全体講評を確認できるモーダルを提供。入力内容は `localStorage` に自動保存され、オフライン復旧時に同期可能。

### 4.3. ペナルティ管理・自動集計機能
- **集計アルゴリズム（3方式切替＆比較）**：
  - **Min-Max正規化（`DIFF_CORRECTION`・標準）**：審査員ごとに有効投票（自バンド・`COMMENT_ONLY`・`NULL`除外）の最高点（MAX）・最低点（MIN）・点差（`Diff = MAX - MIN`）を算出し、`(素点合計 - MIN) × (standardDiff / Diff)` で正規化（既定 `standardDiff = 100`、管理画面の「詳細設定」から 1〜100 で変更可。有効採点2件未満または `Diff = 0` のときは補正係数 `1.0`）。
  - **Zスコア正規化（`Z_SCORE`）**：`50 + 10 × ((素点合計 - 平均) / 標準偏差)`（標準偏差0のときは `50`）。
  - **単純平均方式（`RAW_AVERAGE`）**：素点合計をそのまま平均。
  - 管理画面上で3方式をワンクリック切替でき、「3方式比較列」トグルおよび「3つの集計アルゴリズムの特性」解説モーダルを提供。
- **正規化後の魅力点・技術点按分**：元の素点割合（`rawCharm / rawTotal`, `rawTech / rawTotal`、素点合計0時は50/50）をもとに、正規化後合計点から魅力点・技術点を按分算出。
- **ペナルティ減点の非破壊適用**：オーディション単位の `is_penalty_enabled` トグルとバンド単位の `penalty_deduction` 設定を持ち、正規化計算完了後の最終スコアからのみ減算（生データや正規化値は不変）。
- **タイブレーク順序**：最終スコア降順 → ペナルティ前スコア降順 → 素点合計平均降順 → 素点技術平均降順 → 出演順昇順（完全同値時は同率順位フラグを付与）。
- **結果非表示ガード**：採点必須（`SCORE_AND_COMMENT`）の対象者に未提出者が1名でもいる間は、ランキング・バンド別講評・全体講評をデフォルトで非表示とする。管理者は「未提出ありでもプレビュー表示する」で暫定確認可能。一般部員への公開およびエクスポートは「ステータスが `CLOSED`」かつ「採点必須の未提出者が0名」のときのみ許可。

### 4.4. エクスポート・提出状況モニタリング機能
- **2ファイル構成のExcel (`.xlsx`) / CSV (`.csv`) エクスポート**：
  1. **集計結果＆全採点データ＆全体講評**：Excel 3シート構成（①「総合ランキング集計」②「全採点データ_補正過程」③「全体講評」）。
  2. **バンド別講評シート**：出演バンドごとに1シート（Excelシート名31文字制限・禁止文字サニタイズ対応）＋末尾に「全体講評」シート。各バンドシートには正規化後の魅力点・技術点・合計点とコメントを記載（`COMMENT_ONLY` 等は点数欄 `-` 表示）。
- **提出状況モニタリング**：管理画面「集計」→「提出状況」タブで、対象者全員の提出状態・入力済みバンド数・全体講評入力有無を確認可能。「未提出者のみ表示」フィルタおよび回生別テキストをクリップボードへコピーする「未提出者リストをコピー」機能を提供。

### 4.5. イベント開催回管理機能（管理者権限）
- **新規イベント作成**：イベント名（年号不要）、開催予定日、バンド募集締切（必須）、採点締切（任意）を指定して `DRAFT` 状態で作成（短縮8文字IDを自動採番）。
- **4段階の進行ステータス切替**：
  1. `DRAFT`（バンド募集中）
  2. `ENTRY_CLOSED`（募集締切・調整中）
  3. `ACTIVE`（採点受付中：切替時に採点締切の設定が必須。既存の `ACTIVE` イベントは単一UPDATEで自動的に `CLOSED` へ切替）
  4. `CLOSED`（採点終了・集計）
- **バンド出演順設定**：1バンド目〜Nバンド目の枠にプルダウンでバンドを割り当て（既割当バンド選択時は自動スワップ）。
- **バンド一括登録**：CSV/TSVテキストで一括登録（氏名または学籍番号で部員マスタと自動紐付け、追記／置換を選択可）。
- **採点・コメント義務設定**：現役1〜3回生を対象に、現在の設定状況・回生・出演状況・氏名検索で絞り込み、一括適用または個別3択ボタン（採点＋コメント／コメントのみ／不参加）で即時更新。
- **イベント削除**：イベント名の手入力確認を経て、紐づくバンド・権限・採点データを含めて完全削除。

## 5. 非機能要件（Non-Functional Requirements）

- **性能・応答性**：100ユーザーからの同時リクエストにおいて、採点送信レスポンス1秒以内（Cloudflare Workers + D1 サーバーレス構成）。
- **可用性・信頼性**：DBレベルの複合ユニーク制約による二重送信防止、フロントエンドの送信中ボタン非活性化、オフライン時のローカル下書き保持。
- **セキュリティ**：RBAC（一般部員と管理者の権限分離）、リクエスト毎の最新DBロール参照（JWT CookieにはユーザーIDのみ保持）、学籍番号のHMAC-SHA256不可逆ハッシュ化による個人情報最小化。

## 6. データモデル・スキーマ（Data Schema）

Cloudflare D1（SQLite）+ Drizzle ORM（`src/server/db/schema.ts`）による6テーブル構成：

- **`users`**：`id`, `student_id_hash` (UNIQUE), `google_sub` (UNIQUE, NULL可), `name`, `role` (`ADMIN` | `VOTER`), `enrollment_year`, `is_grade_confirmed`, `created_at`, `updated_at`
- **`auditions`**：`id`, `title`, `event_date`, `deadline` (後方互換用), `entry_deadline`, `scoring_deadline`, `status` (`DRAFT` | `ENTRY_CLOSED` | `ACTIVE` | `CLOSED`), `is_penalty_enabled`, `aggregation_method` (`DIFF_CORRECTION` | `Z_SCORE` | `RAW_AVERAGE`), `standard_diff` (既定 `100.0`), `created_at`, `updated_at`
- **`bands`**：`id`, `audition_id`, `name`, `performance_order`, `penalty_deduction`, `updated_by_user_id`, `created_at`, `updated_at`
- **`band_members`**：`id`, `band_id`, `user_id`, `instrument`, `created_at` ※`UNIQUE(band_id, user_id)`
- **`audition_voters`**：`id`, `audition_id`, `user_id`, `permission_type` (`SCORE_AND_COMMENT` | `COMMENT_ONLY`), `is_submitted`, `submitted_at`, `general_feedback` ※`UNIQUE(audition_id, user_id)`
- **`scores`**：`id`, `audition_id`, `band_id`, `evaluator_user_id`, `tech_score` (NULL可), `charm_score` (NULL可), `comment`, `created_at`, `updated_at` ※`UNIQUE(audition_id, band_id, evaluator_user_id)`

## 7. システム構成・技術スタック（Tech Stack）

- **フロントエンド**：React 19, TypeScript, Vite, Tailwind CSS v4, Lucide Icons, Zod
- **バックエンド / API**：Hono（Cloudflare Workers 上で `/api/*` を処理、Hono RPC 型共有、Zod バリデーション）
- **認証**：Google OAuth 2.0（`@hono/oauth-providers/google` + 学内ドメイン制限 + HTTPOnly JWT Cookie）
- **データベース / ORM**：Cloudflare D1 (SQLite) / Drizzle ORM（ローカル開発・テスト時は `better-sqlite3`）
- **Excel / CSV 処理**：SheetJS (`xlsx`)
- **ホスティング**：Cloudflare Workers（Workers Static Assets によりフロントSPAとAPIを単一デプロイ）

## 8. 画面仕様・UIフロー（Screen Flow）

全イベント依存画面は `/auditions/:id/<tab>` 形式のURLを持ち、共通ヘッダー（`AdminAuditionHeader`）で「表示中のイベント」と進行ステータスを常時確認・切替できる（開催日から半年以上経過したイベントはデフォルト非表示、トグルで表示切替可能）。

- **ログイン画面**：学内Googleアカウントログイン（開発環境ではダミーログイン一覧表示）。初回ログインかつ回生未確定時は「氏名・回生（入部年度）の登録」モーダルを表示。
- **採点画面（`/auditions/:id/scoring`）**：タイムテーブル順のバンド採点カード（自バンド自動除外、保存時自動折りたたみ）＋全体講評カード＋下部固定バー（進捗表示、「マイ順位確認」モーダル、「最終提出する」）。
- **バンド登録画面（`/auditions/:id/bands`）**：登録バンド一覧、募集締切・残り時間表示、全部員向けの新規登録・編集モーダル（現役1〜3回生から検索選択、最終更新者表示）。締切後・募集終了後は一般部員に対して自動ロック。
- **集計画面（`/auditions/:id/results`）**：
  - **管理者向け**：集計アルゴリズム設定・ヘルプモーダル、ペナルティ有効化・3方式比較列トグル、4つのサブタブ（ランキング／バンド別講評／全体講評／提出状況）、未提出時非表示ガード＆プレビュー切替、2ファイルExcel/CSVエクスポート。
  - **一般部員向け**：`CLOSED` かつ採点必須者全員提出後に公開。3つのサブタブ（ランキング／バンド別講評／全体講評）と2ファイルExcel/CSVエクスポート。
- **【管理者】設定画面（`/auditions/:id/setup`）**：イベント新規作成モーダル、左目次付き5セクション（1. 進行ステータス＆締切設定、2. 採点・コメント義務設定、3. バンド出演順の設定、4. バンド一括登録、5. 詳細設定・削除）。
- **【管理者】部員管理画面（`/admin/users`）**：全イベント共通の部員一覧（折りたたみ式、氏名検索・回生・権限フィルタ、ログイン連携状態、権限切替、削除）およびExcel/CSV/TSV一括登録。

## 9. エッジケース・例外処理（Edge Cases）

- **複数バンド掛け持ちユーザー**：`band_members` の多対多関係により、所属するすべてのバンドをUI・API・集計・講評出力から正確に除外。
- **通信切断・遅延**：入力内容を `localStorage` へ自動保存し、通信復旧時の同期ボタンおよび自動再送信に対応。
- **直前のメンバー変更・バンド脱退**：管理者が `band_members` を更新すると、次回リクエスト・画面再読み込み時に自バンド除外判定へ即座に反映（JWTに所属バンドやロールをキャッシュしない設計）。
- **ステータスおよび締切日時による自動ロック**：`status !== 'DRAFT'` または `entry_deadline` 超過時は一般部員のバンド編集をサーバー側で `403` 拒否。`scoring_deadline` 超過時は提出済み・保存済み採点の変更を `403` 拒否。
- **同点（タイ）および0除算ガード**：点差 `0` や有効採点1件以下時の補正係数 `1.0` フォールバック、標準偏差 `0` 時の偏差値 `50` フォールバック、多段階タイブレークおよび同率順位表示を実装。
- **学外者および未登録者のアクセス遮断**：Google OAuth時のドメイン制限に加え、`ALLOW_UNREGISTERED_DOMAIN_USERS=false` 時は部員マスタ未登録者のログインを遮断。
